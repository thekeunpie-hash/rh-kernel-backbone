How to Actually Contribute to the Lean Riemann Hypothesis Proof

On November 26, 2026, leanprover-community/riemann-hypothesis moved its 58,947-file Alpöge cleanup to branch alpoge and switched main to Luke Sernau and Anthropic’s readable grh-lean proof: 802 Lean files, roughly 300,000 lines of code, zero sorry, and standard axioms only. This page is a plain working manual for people who want to read the proof or land a clean PR without stepping on the traps that waste hours.

A quick note on verification scope, because precision matters here. Andrew Sutherland at MIT independently verified the grh/ readable release across four independent checkers (leanchecker, nanoda, con-leche, and con-ron), producing a byte-identical 4.49 GB kernel export on two machines (MIT report). Since that switch, upstream main upgraded to Lean v4.37.0-rc1, added TauCetiProject/TauCeti as a dependency, and started accepting community cleanup PRs; every commit on main is checked continuously by GitHub Actions lake build and frozen challenge-file guards.

1. The first trap: shorter source can produce a larger kernel proof

If your instinct is to compress proofs by packing lines with semicolons or replacing explicit have steps with grind, simp_all, and aesop, stop and look at what happened when MIT exported both versions of grh-lean:

Edition Code lines Kernel export Cold build
grh/ readable (basis of main) 299,902 4.49 GB 32m 12s
grh-compact/ line-packed 76,149 (−74.6%) 5.17 GB (+15.3%) 33m 32s

Rule of thumb for PRs: delete dead declarations, inline redundant single-caller wrappers, and offload general lemmas to TauCeti or Mathlib. Do not golf readable proofs into dense tactic one-liners. Explicit intermediate have bindings preserve kernel term sharing and keep the proof both smaller in the kernel and faster to maintain.

2. How to land a clean PR in under an hour

Full cold builds take half an hour. You almost never need one to prepare a good PR.

  1. Leave frozen files alone. The repository’s challenge files workflow rejects any PR that modifies Challenge.lean, comparator.json, src/Statements.lean, or the build configuration. Keep all edits inside src/Lib/, src/New/, or documentation.
  2. Check open PRs before touching a module. The repository merges quickly and two people editing the same file will collide on rebase.
  3. Build only the module you edited (and its immediate downstream caller). If your edit does not change a declaration’s type signature, downstream modules do not need to be re-elaborated locally.
  4. Verify zero sorry and standard axioms. Never introduce set_option maxHeartbeats or set_option backward.* to make a shortened proof pass; the goal is to remove those flags, not add them.
  5. Keep each PR small and single-purpose. One to three files with one clear reason (dead lemma removal, single-caller flattening, backward.* cleanup, or TauCeti replacement) gets reviewed and merged far faster than a 20-file refactor. 
# 1. Check active open PRs to avoid file collisions
gh pr list --repo leanprover-community/riemann-hypothesis --state open --limit 30

# 2. Build only the single module you changed
lake build New.UpperBound.StandardLines

# 3. Confirm no sorry or custom axioms crept in
lake env lean -e 'import Main; #print axioms riemannHypothesis'

4. The proof spine in six real Lean files

Every symbol below is verified directly against the grh-lean kernel environment. If you want to understand how the 802-file proof replaces Alpöge’s Arakelov slope and Taylor–Wiles patching machinery without reading 300,000 lines, read these six files in order:

  1. New.Data.enough_forms src/New/Reduction/ShortAndEnough.lean

    Combines short-form height upper bounds (New/UpperBound) with the Poisson-summation spanning sieve (New/Spanning) to construct enough short integral automorphic forms.

  2. New.Data.integral_forms_long src/New/Determinant/Twist/LongForms.lean

    Combines first-order congruences (New/Congruences), single-step lifts (New/OneLift), and the Gram-determinant product formula (New/Determinant) to force any large integral family to be long.

  3. New.star_inequality src/New/Reduction/MainInequality.lean

    Pinches the upper and lower covolume bounds against each other so the main height term cancels, isolating a prime-remainder estimate.

  4. New.Data.primeRemainder_le  →  New.LFunction_ne_zero_of_primeRemainder_le src/New/Reduction/OneSidedBound.lean  ·  src/New/Reduction/Zeros/Criterion.lean

    Converts the star inequality into a one-sided Landau bound on prime remainders and rules out zeros of Dirichlet L-functions in the half-plane Re(s) > 1/2.

  5. New.grh  →  New.zeta_zeros_on_line, New.zeros_on_line src/New/Main.lean

    Reflects the zero-free right half-plane across s ↔ 1 − s via the functional equation.

  6. riemannHypothesis, riemannZeta_eq_zero_re, LFunction_eq_zero_re src/Main.lean

    Top-level declarations (no Main namespace) matching Mathlib’s canonical RiemannHypothesis statement with [propext, Classical.choice, Quot.sound] only.

5. Where the earlier Alpöge proof went

Levent Alpöge’s original 175,187-file formalization and the community’s cleanup down to 58,947 files (Batch 23, commit 756a70250) are preserved intact on branch alpoge. Historical shrinkage charts live on rh-shrink.github.io, contributor records are on profiles.html, and the full multi-chart tracker remains available at index.html.
